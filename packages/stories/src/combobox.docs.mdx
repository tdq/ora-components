# ComboBox

ComboBoxes combine a text input with a dropdown list, letting users either type to filter or select from a predefined set of options. The `ComboBoxBuilder<ITEM>` provides a generic reactive API for constructing searchable comboboxes with filtering, programmatic value control, custom item rendering, and keyboard navigation — all driven by RxJS observables for live-updating bindings.

The combobox follows Material Design 3 conventions and supports two built-in styles: tonal and outlined.

---

## When to use

Use a combobox when users need to search or filter through a list of options to make a selection:

- **Search-as-you-type** — the user types to narrow down a long list of options (e.g. "Find an account by name")
- **Combined input + selection** — the user can either type a value or pick from a dropdown
- **Large option sets** — when a standard select dropdown would be too long to scan

Use a standard `ListBox` (non-searchable) when the option list is short (fewer than 10 items) and the user does not need to type to find a value.

---

## Usage

```typescript
import { ComboBoxBuilder, ComboBoxStyle } from '@tdq/ora-components';
import { of } from 'rxjs';

const combobox = new ComboBoxBuilder<string>()
  .withItems(of(['Invoice', 'Payment', 'Credit Note', 'Adjustment']))
  .withCaption(of('Transaction Type'))
  .withPlaceholder('Type to search...')
  .withStyle(of(ComboBoxStyle.TONAL))
  .build();

document.body.appendChild(combobox);
```

## Builder API

All builder methods return `this` for chaining. Pass RxJS observables into the reactive setters — the component handles subscription lifecycle and automatically cleans up when detached from the DOM.

- **`withItems`** — `(items: Observable<ITEM[]>): this`
  Sets the list of items displayed in the dropdown. Items are filtered by caption when the user types.

- **`withValue`** — `(value: Observable<ITEM \| null> \| Subject<ITEM \| null>): this`
  Binds the value driving the dropdown selection/highlight. Passing a `Subject` gives two-way binding — the component writes the selection into it and reads incoming values back. Passing a plain read-only `Observable` only reads: the displayed text and highlight follow the stream, but user selections are **not** written back to it (there's nothing to write to). While the user is actively filtering (typing), an external emission updates selection state but does not overwrite the text they're typing — it resyncs once the popup closes.

- **`withCaption`** — `(caption: Observable<string>): this`
  Sets the label text displayed above the input. Updates reactively when the observable emits.

- **`withPlaceholder`** — `(placeholder: string): this`
  Sets the placeholder text shown inside the input when no value is selected.

- **`withAriaLabel`** — `(label: string \| Observable<string>): this`
  Sets the accessible name used when no `withCaption` is set. Priority is `caption` (via `aria-labelledby`) > `ariaLabel` (via `aria-label`) > `placeholder` (via `aria-label`). Accepts a plain string or an observable. In dev mode, a console warning fires if none of the three accessible-name sources is configured at build time.

- **`withItemCaptionProvider`** — `(provider: (item: ITEM) => string): this`
  Converts an item to its display string in the dropdown and input. Defaults to `String(item)`.

- **`withItemIdProvider`** — `(provider: (item: ITEM) => string \| number): this`
  Produces a unique ID for each item, used for accessibility and selection comparison. Defaults to `String(item)`.

- **`withStyle`** — `(style: Observable<ComboBoxStyle>): this`
  Applies one of the combobox style variants. Defaults to `ComboBoxStyle.TONAL`.

- **`withListWidth`** — `(width: Observable<string>): this`
  Sets the width of the dropdown list. Accepted values: `'match-input'` (matches input width), `'auto'` (content-sized with min-width of input), or any CSS width string.

- **`withEnabled`** — `(enabled: Observable<boolean>): this`
  Controls the interactive state. When `false` the input is disabled with reduced opacity.

- **`withError`** — `(error: Observable<string>): this`
  Sets the validation error message shown below the input. An empty string clears the error.

- **`withClass`** — `(className: Observable<string>): this`
  Appends additional CSS class names to the root container element.

- **`withVisible`** — `(visible: Observable<boolean>): this`
  Controls visibility of the combobox container.

- **`asGlass`** — `(isGlass?: boolean): this`
  Enables the glass-effect variant with frosted background and blur. Defaults to `true`.

- **`withMaxHeight`** — `(maxHeight: number \| Observable<number>): this`
  Sets the preferred popup list height in pixels (or a reactive observable), clamped to available viewport space. Default `256`. The list's own `<ul>` scrolls internally at this height — the popover wrapper itself never scrolls.

- **`withFilterDebounce`** — `(ms: number): this`
  Overrides the default 150ms debounce applied to filtering once the item list reaches 100 items or more (below that threshold, filtering is always synchronous). Pass `0` to disable debouncing entirely, even for large lists. Enter/Arrow keys/Home/End/PageUp/PageDown always flush any pending debounce immediately, so fast "type + Enter" never acts on a stale filtered list.

- **`build`** — `(): ComboBoxElement<ITEM>`
  Constructs and returns the root element, extended with a small imperative API:
  - **`select(item: ITEM \| null): void`** — selects an item programmatically: updates the displayed text, highlight, writes the value back (if bound to a `Subject`), and closes the popover.
  - **`open(): void`** — opens the dropdown.
  - **`close(): void`** — closes the dropdown.

  Subscribe to observables and wire up the DOM. Call once per builder.

## Viewport-Aware Positioning

The dropdown popover measures available space against the real browser viewport (not any bounding container the combobox happens to sit inside — see `popover.ts`'s `_position()`), and adapts in two ways when the input is near the bottom of the visible viewport:

- **Flip** — if there isn't enough room to open downward but there's more room above than below, the popover opens **above** the input instead of below it.
- **Height clamping** — the popover's height (bounded by `withMaxHeight`, default 256px) is clamped to whichever side's available space is smaller, so it never runs off either edge of the viewport — only the list `<ul>` scrolls internally, the popover wrapper itself never does.

Because this is measured against the real viewport, it can't be demonstrated correctly inside a docs page's embedded `<Canvas>` iframe (a bounded/short iframe still leaves plenty of real page below it, so no flip occurs; forcing it with `position: fixed` would instead escape the iframe and float over the whole docs page). See it live in the standalone `NearViewportBottom` story instead: [ComboBox → NearViewportBottom](../?path=/story/components-combobox--near-viewport-bottom).

## Keyboard

| Key | Action |
|---|---|
| `Tab` / `Shift+Tab` | Move focus into and out of the combobox |
| `Arrow Down` | Open the dropdown and navigate to the next item (wraps) |
| `Arrow Up` | Navigate to the previous item (wraps) |
| `Home` / `End` | Jump to the first / last item while the dropdown is open |
| `Page Up` / `Page Down` | Move focus 10 items back / forward while the dropdown is open |
| `Enter` | Select the focused item |
| `Escape` | Close the dropdown without selecting |
| `Space` | Falls through to allow typing multi-word search terms |

### Additional notes

- **Input height** is 48px (`h-[48px]`) for consistency across variants.
- **Dropdown popup** is powered by `PopoverBuilder` with a `ListBoxBuilder` (BORDERLESS style) as its content. The popup has a max-width of 300px.
- **Filtering** activates only when the user starts typing; the initial dropdown shows all items.
- **Selected item** is highlighted with bold text and `bg-on-secondary-container/20`.
- **Focused item** (keyboard navigation) is highlighted with `bg-on-surface/12` (not applied when the item is also selected).
- **"No results"** message appears when the filter produces no matches; the `<ul role="listbox">` remains in the DOM for accessibility.
- <a id="virtualization-details" /> **Virtualization**: the dropdown's inner `ListBoxBuilder` is always virtualized — including in ComboBox mode — via `VirtualRowsViewport`. Only a window of rendered rows exists in the DOM at any time; each rendered `<li>` still carries a stable, item-derived `id` (via `withOptionIdProvider`), which ComboBox uses to compute `aria-activedescendant` without indexing into the DOM.
- **Error state** applies a red outline (`outline-error`) around the input container.
- **Disabled state** applies `opacity-38` and `cursor-not-allowed`.
- **Accessibility**: The input carries `role="combobox"`, `aria-autocomplete="list"`, `aria-expanded`, `aria-controls`, and `aria-activedescendant` for full ARIA combobox pattern compliance.
- **Glass effect** applies `glass-effect` to the input, the popover, and the listbox items with translucent colours and backdrop blur.
